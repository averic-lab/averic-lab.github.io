# 숏폼 영상 빌드 (게시 제외 — `_` 접두 폴더)

홈페이지 목업처럼 **앱 화면을 HTML/CSS로 그린 페이지**를 프레임 단위로 캡처해 mp4 로 만든다.
한 편 = 페이지 한 장이고, `?lang=xx`로 20개 언어가 같은 페이지에서 나온다.

| 파일 | 역할 |
|---|---|
| `shorts.json` | **단일 출처.** `videos`(편 목록, `home:true`면 홈 해질녘에 나옴) + `langs`(영상에만 나오는 문구 20개 언어) |
| `gen.py` | `data/<언어>.js`(페이지가 읽는 문구 묶음) + 검토 페이지 `preview/shorts/` 생성 |
| `a.html` / `b.html` | 영상 페이지. 540×960 CSS 캔버스(×2 = 1080×1920). 글자는 `data-k`/`data-h`로 채운다 |
| `shorts.css` | 캔버스·자막·공통 엔딩 + `../style.css` 앱 목업을 평평하게 펴는 덮어쓰기 |
| `engine.js` | 언어 데이터 로드, 결정적 타임라인(`data-t`/`data-fx`, `render(ms)`), 엔딩, Intl 시각·숫자 형식 |
| `render.mjs` | Playwright 로 `render(ms)`를 1/30초씩 캡처 → ffmpeg(libx264, yuv420p, faststart). `--stills`·`--check` |
| `render_all.sh` | 언어 × 편 전체 렌더(동시 4개) → `media/shorts/<언어>/<id>.mp4` + `.jpg` → `gen.py` 재실행 |
| `audio.py` | 배경음악 + 효과음을 섞어 렌더된 mp4 에 넣는다(영상은 다시 인코딩하지 않음). `render_all.sh` 가 자동으로 부른다 |
| `check_tokens.mjs` / `check_layout.mjs` | 전 언어 토큰·undefined 검사 / 0.5초 간격 레이아웃 검사(1초 이상 지속되는 문제만). 사용법 튜토리얼 편에서 처음 씀 |
| `check_overlap.mjs` | 글자끼리·글자와 알림 카드의 겹침 중 **한국어에 없는 것**이 0.5초 이상 이어지면 보고(0.25초 간격). 떠나기 전 필수품 편에서 처음 씀 |

## 문구 출처 — 한 곳씩만

⚠️ **번역을 새로 쓰거나 고치기 전에 앱 저장소 `.claude/translation_glossary.md`를 먼저 읽는다** — 언어별 안부·대상자·보호자 용어와 금지어(신호·후견·건강검진 계열)의 유일한 기준이다.
`shorts.json` `langs`, `3d/manual.json`(엔딩·제목), `3d/upload_desc.json`, 공유 드라이브 `upload.json`의 설명은 앱·서버가 생성하지 않아 **용어집이 바뀌어도 자동으로 따라오지 않는다** — 직접 맞춘다(2026-10-05 용어 통일 때 3d 쪽이 빠졌었다).

| 문구 | 출처 |
|---|---|
| 자막·통화 기록·말풍선·도시·딸 이름 등 영상 전용 | `shorts.json` `langs` |
| 앱 화면(대시보드 카드, "마지막 확인: 방금 전" 등) | 앱 저장소 `translations/*.dart` — `gen.py`의 `APP_KEYS` (홈 추출 계약 `extract_strings.py KEYS`는 늘리지 않는다) |
| 푸시 제목 `✅ 오늘 안부 확인 완료` | 서버 저장소 `i18n/messages.py` `push_auto_report_title` |
| 엄마 호칭, 엔딩 문장 | `i18n/translations.json` `nick1`, `dawn_q3_html` |
| 시각·날짜·숫자 형식 | 브라우저 Intl (언어별 12/24시간제, 자릿수 구분 자동) |

B의 두 도시 시각은 `home_tz`/`away_tz`로 **실제 시간대 계산**이다(집 밤 11:40 기준). 도시를 바꾸면 자녀 쪽이 낮 시간인지 확인할 것.

## 렌더

```bash
brew install ffmpeg                                    # 1회
npm i --prefix <임시 폴더> playwright-core
export PLAYWRIGHT_CORE=<임시 폴더>/node_modules/playwright-core
export CHROMIUM_PATH="$HOME/Library/Caches/ms-playwright/chromium-1243/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing"

python3 gen.py                                         # 데이터 먼저
node render.mjs b.html --check --lang de               # 글자 넘침·겹침 자동 검사
node render.mjs a.html --stills 1.5,8.5 /tmp/s --lang ja   # 정지 화면 확인
./render_all.sh                                        # 전체(편 × 20개 언어) — 또는 ./render_all.sh en ja
VIDEOS=neighbor-friends ./render_all.sh ko             # 그 편만(쉼표로 여러 편) — 새 편을 만들 때 다른 편을 다시 인코딩하지 않는다
```

브라우저에서 `a.html?lang=en&play`로 열면 실시간 재생으로 흐름을 볼 수 있다.

## 새 영상 추가

1. 페이지를 새로 만든다. 기존 편에서는 골격(`engine.js`·`shorts.css` 로드, `render(ms)` 계약)만 확인하고 장면 구성·연출은 가져오지 않는다. 문구는 전부 `data-k`/`data-h`로, 새 문구는 `shorts.json` `langs` 20개 언어에 추가.
2. `shorts.json` `videos`에 `{id, page, title, date}`를 넣는다. **홈에 넣지 않을 영상은 `home`을 빼거나 false.**
3. `./render_all.sh` → 검토 페이지 언어 폴더와 공개 영상 페이지(`/{언어}/shorts.html`)에 자동으로 나타난다(최신 날짜가 위). 홈 해질녘에는 `home:true`인 편만 나온다.
4. ⚠️⚠️ **단 2026-10-10 이후 날짜의 편은 유튜브에 올라가기 전까지 사이트 어디에도 나오지 않는다**(사용자 지시).
   `i18n/build.py` 의 `YOUTUBE_GATE_FROM` 이 날짜로 자동으로 거른다 — 홈 해질녘·영상 페이지·사용설명·검토 페이지 전부.
   publish.json 에 그 (편, 언어)의 youtube_id 가 생기면 다음 빌드에서 **그 언어만** 유튜브 플레이어로 나타난다(포스터 jpg 필요, mp4 불필요).
   그 전에는 jpg 를 커밋하지 않는다(링크가 없어도 URL 로 받을 수 있다). 예외는 그 편에 `"after_youtube": false`.
   ⚠️ **새 편의 mp4 는 유튜브 뒤에도 커밋하지 않는다**(2026-11-15 사용자 결정) — `.gitignore` 의 `media/shorts/*/*.mp4` 가 막는다. 유튜브로 재생하므로 필요 없다. 이전에 커밋된 mp4(홈 해질녘 등)는 계속 추적된다. `after_youtube: false` 편만 `git add -f`.

## 소리 (배경음악 · 효과음)

- **배경음악 기본값**은 `shorts.json` 최상위 `audio`(We'll Be Okay, 0초부터)이고, 편마다 다른 곡을 골라도 된다(편에 `"audio": {"bgm": …, "bgm_start": …}`). 소리를 빼려면 그 편에 `"audio": false`. 원본은 `../media/bgm/`.
- **효과음**: 페이지의 `window.SFX = [{t, file, rel?, duck?}]`. `t`는 **화면에 팝업이 뜨는 시각**(그 요소의 `data-t`와 같은 값). 파일 앞 무음은 `audio.py`가 재서 당기므로 신경 쓰지 않는다. 원본은 `../media/sfx/`.
  효과음은 기본 **2초**에서 자른다. 타이핑처럼 화면 동작과 길이를 맞춰야 하는 소리는 `len`(초)으로 늘린다 — 글자가 다 찍히는 시간과 같게.
- **크기 기준**(2026-09-24 실청취로 정함 — 처음 -16 LUFS·효과음 +8~25dB는 "볼륨을 반으로 줄여도 크고 튄다"였다):
  - 전체 -22 LUFS(-20에서 실청취로 2 더 낮춤), True Peak -1.5 dBTP 이하
  - 배경음악 페이드인 0.8초, 페이드아웃은 영상 끝 2초에만(엔딩 문구 동안 유지)
  - 효과음은 **그 순간 배경음악보다 +3~6dB**(기본 +4.5, cue의 `rel`로 조정) — 튀지 않게. 그 순간에도 Short-term -16 LUFS 이하
  - 더킹은 앱 알림음(`duck: true`)에만 2.5dB. 효과음 앞뒤 짧은 페이드
  - `audio.py`가 매번 이 기준을 실측해 보고하고, 넘으면 `⚠`를 찍는다
- 곡을 고를 때는 **저음 위주·타악기 없는 곡**이 효과음과 덜 겹친다. 고음이 밝은 곡(Valley Sunset, Serene Moments)은 효과음을 가린다.
- ⚠️ **음원 원본과 `.mix/`는 커밋하지 않는다**(`.gitignore`). Mixkit 라이선스가 파일 단독 재배포를 금지하고, `media/`는 그대로 공개되는 폴더다. 라이선스 증빙은 `../media/bgm/LICENSE-증빙.md`·`../media/sfx/LICENSE-증빙.md`(역시 커밋 제외 — 원본과 함께 보관).

## 지난 편에서 얻은 기술 메모 — 본뜨지 않는다

h·i·j 편을 만들며 알게 된 **기술 사실**만 남긴다. 장면 구성·연출·화면 구도·길이·곡은 **편마다 새로 정하고 이전 편을 따라 하지 않는다**(2026-11-15 사용자 지시 — 비슷한 쇼츠가 나오지 않게). 기존 편 파일은 구현 방법을 확인할 때만 연다.

- **편 전용 곡**: 편에 `"audio": {"bgm": …, "bgm_start": …}`를 두면 `audio.py`가 최상위 곡 대신 그 곡을 쓴다.
- **용량**: 입자가 많은 장면은 crf 18이면 편당 16MB를 넘는다 — 페이지에 `window.CRF = 28`(`render.mjs`가 읽는다). 유튜브용 원본은 `CRF=18 node render.mjs <편>.html <출력> --lang xx`로 따로 렌더하고 `.mix/<편>.m4a`를 `-c copy`로 붙인다(커밋하지 않는다).
- **썸네일 덮어쓰기**: `render_all.sh`가 jpg를 1초 지점으로 다시 만든다. 다른 지점이나 따로 그린 그림을 썼다면 렌더 뒤 같은 파일명으로 다시 덮어쓴다.
- **검사 도구**: `--check`는 새 클래스를 못 본다 — 새 구조면 `check_tokens.mjs`·`check_layout.mjs`·`check_overlap.mjs`로 잰다.
- **앱 화면을 그릴 때**: 배치·색·상태별 차이는 앱 위젯 코드를 읽고 맞춘다. 앱 문구는 `gen.py`의 `I_APP_KEYS`/`I_SRV_KEYS`/`I_OPT_KEYS`(→ `L.app`·`L.srv`)에서만 가져온다. 자막 속 앱 낱말을 토큰(`@set` 등)으로 두면 화면 글자와 자막 글자가 언어마다 같아진다.
- **위치 재기**: transform 애니메이션 중에는 `getBoundingClientRect`가 섞인 값을 준다 — 렌더 중 다시 재야 하면 offset 체인(i.html `posIn()`)으로 잰다.
- **사실 주장 문구**: 가격 비교("점심 한 끼 정도")·시차 같은 숫자는 번역이 아니라 사실이다 — 나라별로 검색해 확인하고, 한 편 안에서 같은 숫자가 장면마다 달라지면 안 된다. 앱 동작을 보여 주면 서버 동작 순서 그대로(예: 배터리 — 안부 전송 때 배터리 부족 → 꺼짐 → 다음 날 미수신 체크 → 방전 추정).
- **언어별 조합**: 천 단위·'라벨: 값' 구분자는 용어집 §3·§5대로 직접 만든다(Intl은 es에서 1482를 묶지 않아 앱 1.482와 다르다). 숫자는 `-u-nu-latn`, 퍼센트는 `Intl.NumberFormat(style:'percent')`(tr `%12`, fr `12 %`). 글자를 쪼개는 연출은 아랍어·태국어·힌디어를 **단어** 단위로(`Intl.Segmenter`) — 글자로 쪼개면 모양이 깨진다. 아랍어는 방향(화살표·넘김·손가락)을 거울로.
- **박자에 맞추는 편이라면**: 박 측정은 `librosa.beat.beat_track(..., start_bpm=…, tightness=400)`(기본값은 위상이 흔들린다). 박에 맞춰 *시작*한 큰 변화는 40~80ms 늦게 보인다 — 맞출 것은 시작이 아니라 가장 크게 바뀌는 순간이다. 검사는 완성 mp4의 프레임 차이 정점과 박 격자의 오차로 한다.
- **겹친 효과음**: 0.2~0.4초 간격 효과음은 `audio.py` 측정창(0.5초)에 함께 잡혀 기준을 넘는다 → 앞 소리의 `rel`을 낮추거나 뒤 소리를 조금 민다.
- **깜빡임**: 초당 3회 미만, 빨간 화면 전체 깜빡임 금지.

## 규칙

- ⚠️ **영상 앞을 잘라 타임라인을 옮기면(`T0`) engine.js 의 `data-t` 요소도 같이 옮긴다** — 공통 엔딩(`mountEnding`)과 `data-t` 는 `window.extra` 를 거치지 않고
  '영상 시각'으로 움직인다. j.html 은 `VT(박) = 박*B - T0 - VLEAD` 로 넣는다. 빠뜨리면 엔딩이 그만큼 늦게 떠 **빈 화면**이 생기고 로고가 영상 끝 뒤로 밀린다(2026-10-10, 1:22–1:26 빈 화면).
- ⚠️ **겹침 검사 — 여백·넘침 검사로는 요소끼리의 겹침이 안 잡힌다 (2026-10-11)** — 언어마다 알림 카드 줄 수가 달라(한국어 2줄 → 독일어 4줄) 고정 좌표에 둔 각주·라벨이 카드에 가린다.
  떠나기 전 필수품 편에서 배터리 각주(17개 언어)와 걸음수 라벨(스페인어·포르투갈어)이 다국어 렌더 뒤에야 발견됐다. 다국어 렌더 **전에** `node check_overlap.mjs <편>.html <언어들>` 이 전부 OK 여야 한다.
  카드가 길어지는 자리는 고정 top 대신 카드 높이를 재서 아래 요소를 밀거나 위 요소와 함께 올린다(j.html `battLay`, 걸음수 장면).
- **빈 화면 검사** — 렌더 전에 영상 전체를 .25초 간격으로 훑어, 보이는 글·상자·엔딩이 하나도 없는 구간이 .5초 넘게 이어지면 실패로 본다. 장면 사진 몇 장으로는 장면 *사이*의 빈틈을 못 잡는다.
- **벽시계·CSS 무한 애니메이션을 쓰지 말 것.** 모든 움직임은 `render(ms)`의 함수여야 한다.
- **폰 목업은 `.pw` 래퍼를 `scale()`로만 줄인다** — 안쪽 좌표는 홈페이지 실측값(352×722).
- **폰 안 글씨는 영상에서 읽히지 않는다.** 보여줘야 할 알림·카드는 `.float`으로 확대해 띄운다.
- **안전 영역**: 위 8%·아래 20%·오른쪽 12%는 틱톡·릴스 UI가 덮는다.
- ⚠️ **가운데 정렬과 좌우 여백 (2026-10-10, j.html 에서 사용자 지적)** — 장면의 내용(헤드라인·카드·폰·보드)은 **화면 정가운데 x=270**에 맞추고, **좌우 모두 65px(12%) 안쪽**(65–475)에 둔다.
  왼쪽 여백은 **네이버 클립이 왼쪽을 잘라 재생하는 경우**가 있어서, 오른쪽은 위의 틱톡·릴스 UI 때문이다(공식 수치는 찾지 못해 타이틀 세이프 10%보다 넉넉히 잡은 값).
  "오른쪽 12%"만 보고 0–475 의 가운데(x=247)에 맞추면 **화면 전체에서는 왼쪽으로 치우쳐 보인다** — j.html 첫 렌더가 그랬다. 두 개를 나란히 놓는 장면(폰 두 대·시계 두 개)은 **묶음 전체**의 가운데가 270이어야 한다.
  검사: 장면 사진에 270 중심선과 65·475 여백선을 겹쳐 눈으로 본다(요소 경계 검사만으로는 치우침이 안 잡힌다). a~i 편은 247 기준이다 — 다시 렌더할 일이 생기면 함께 고친다.

## 인물을 그릴 때 — 기술 메모

인물의 생김새·화풍·표정 연기는 **편마다 새로 정한다**(고정 캐릭터 재사용 규칙은 2026-11-15 폐기 — 비슷한 쇼츠가 나오지 않게). 아래는 기술 사실만이다.

- 회전은 `setAttribute('transform', 'rotate(각도 cx cy)')`로 축을 명시한다(SVG 안에서는 CSS `transform-origin`보다 확실하다). 머리는 목, 팔은 어깨, 다리는 엉덩이가 축.
- 인물을 따라가는 것(조명·입김 등)은 `getBoundingClientRect()`로 그 부위 위치를 매 프레임 재서 놓는다(캔버스가 540×960 CSS px라 좌표가 그대로 맞는다).
- 인물 정지 화면은 **얼굴을 잘라 확대해서** 본다 — 1080×1920 전체 화면에서는 얼굴 결함이 안 보인다.
